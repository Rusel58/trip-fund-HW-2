# TripFund — сбор на поездку команды

Контракт принимает взносы в одном ERC-20.
После дедлайна организатор получает всю учтённую сумму, если цель достигнута; иначе каждый
участник самостоятельно возвращает свой вклад.

## Запуск

Нужны Git и [Foundry](https://getfoundry.sh/introduction/installation/).
После установки `foundryup` выберите версию Foundry и склонируйте проект:

```bash
foundryup --install v1.8.5
git clone --recurse-submodules --shallow-submodules https://github.com/Rusel58/trip-fund-HW-2.git
cd trip-fund-HW-2
forge build
forge test
```

Если проект уже склонирован без зависимостей:

```bash
git submodule update --init --recursive --depth 1
```

Версии зависимостей закреплены в Git и `foundry.lock`:

| Зависимость | Версия |
| --- | --- |
| Foundry | `v1.8.5` |
| Solidity | `0.8.30` |
| OpenZeppelin Contracts | `v5.4.0` |
| forge-std | `v1.16.2` |

Компилятор указан в `foundry.toml` и скачивается при первой сборке. EVM target — `cancun`.

## Как работает сбор

При создании задаются токен, организатор, цель в минимальных единицах токена и дедлайн
в секундах Unix. Нулевые адреса, нулевая цель и дедлайн не в будущем отклоняются.
Параметры хранятся как `immutable`.

- `contribute(amount)` принимает положительный взнос до дедлайна. Повторные взносы суммируются.
- `withdraw()` доступен только организатору после дедлайна, если собрано не меньше цели.
  Всю учтённую сумму можно забрать один раз.
- `refund()` доступен после дедлайна при недоборе. Каждый участник забирает свой полный вклад;
  повторный возврат отклоняется.

Достижение цели не разрешает досрочный вывод. Взнос за секунду до дедлайна ещё проходит,
ровно в дедлайн — уже нет.

`contributions(address)` показывает вклад участника. После возврата он обнуляется.
`totalRaised` хранит сумму всех принятых взносов и после выплат не уменьшается.

Прямой перевод через `token.transfer(address(fund), amount)` не учитывается как взнос
и не влияет на исход сбора. Эти токены остаются на контракте после всех выплат.
Для вывода используется `totalRaised`, а не весь токенный баланс контракта.

## Пример взноса

Участник сначала разрешает контракту списать токены, затем вызывает `contribute`.
Оба вызова выполняются от одного адреса:

```solidity
uint256 amount = 10 * 10 ** 18; // 10 токенов с 18 decimals

token.approve(address(fund), amount);
fund.contribute(amount);
```

Для переводов используется `SafeERC20`. Учёт меняется до внешнего вызова токена;
если перевод возвращает `false` или откатывается, изменения тоже откатываются.
От повторного входа защищает `ReentrancyGuard`. События `Contributed`, `Refunded` и `Withdrawn`
содержат адрес и сумму.

Токен должен быть без комиссии за перевод и без rebasing. Для локальных тестов есть
`MockERC20` на OpenZeppelin ERC20 с 18 decimals и методом `mint` для выдачи токенов.

## Тесты

В `test/TripFund.t.sol` проверяются параметры создания, повторные взносы, граница дедлайна,
балансы, события, успешный сбор, возвраты и прямые переводы. Там же три fuzz-теста:
накопление вкладов, вывод при успехе и возвраты при недоборе.

В `test/TripFundTransfers.t.sol` — ошибки перевода (`false` и revert), повторная попытка
после ошибки, порядок обновления состояния и защита от повторного входа.
Вспомогательные токены лежат в `test/mocks/`.

```bash
forge test -vv
forge fmt --check
```

GitHub Actions запускает форматирование, сборку и тесты при push и pull request.
